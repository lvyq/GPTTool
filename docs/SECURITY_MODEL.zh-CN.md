# 安全模型

## 保护目标

- 用户账户和设备之间不能越权访问；
- 公网服务不能读取官方 ChatGPT/Codex 登录凭据；
- CDP 调试端口不能从局域网或公网直接访问；
- 更新包必须可验证来源和完整性；
- 断线和重启不能重复执行同一条排队消息。

## 已实现控制

- Relay 仅监听 `127.0.0.1`，由 Nginx 提供 TLS；
- 登录 Cookie 使用 HttpOnly、Secure、SameSite；
- 密码使用带随机盐的抗暴力哈希，登录/注册/配对均有限流；
- 设备密钥随机生成，服务端只保存哈希；
- WebSocket upgrade 再次校验账户、Origin 和设备归属；
- CDP 和本地控制端口只绑定回环地址；
- 附件有大小、数量、分块和超时限制；
- 更新清单使用 Ed25519，安装包验证 SHA-256，并限定与清单同源的 HTTPS URL；
- 配置文件以受限权限写入，生产密钥不进入 Git。

## 明确不保护的场景

- 设备本身已被恶意软件或管理员账户控制；
- 用户主动把配对二维码、访问会话或服务器密钥发给第三方；
- 自托管者关闭 TLS、开放数据库端口或使用弱口令；
- 上游官方客户端、Electron/Chromium 或操作系统自身的未知漏洞。

## 数据最小化

Relay 保存账户、绑定设备、登录会话、任务索引、压缩快照、队列、偏好、额度快照和附件元数据。官方原始会话数据库保留在本机，由官方客户端管理。部署者应配置备份保留期和数据删除流程。
